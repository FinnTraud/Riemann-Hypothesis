# RH knowledge-graph RAG — MCP server

Hybrid **knowledge graph + retrieval** server over the 50 RH documents in `../docs/`.
Three layers make it "bulletproof":

1. **Knowledge graph** — documents + concepts + atomic *claims* as nodes, typed
   relations as edges (`equivalent_to`, `implies`, `reduces_to`, `refuted_by`,
   `obstruction_for`, `models`, `blueprint_for`, …). Enables *traversal* instead of mere
   similarity search.
2. **Claims with status** — each key statement carries `status: proven|open|refuted`.
   That way the assistant can never treat a refuted statement (e.g. the Mertens
   conjecture) as true.
3. **Hybrid retrieval** — BM25 (lexical, matches math symbols/names) + graph expansion
   (a hit is enriched with equivalent/refuting neighbors). Embeddings optionally retrofittable.

## Files
```
kb/
  build_kb.py          # builds kb/index/kb.json from docs/ + manifest.json + graph/
  core.py              # shared query logic (stdlib)
  query.py             # CLI for testing (stdlib, no installation)
  server.py            # MCP server (FastMCP) — exposes the tools
  requirements.txt
  graph/
    nodes.json         # curated concept nodes
    edges.json         # curated typed relations (the intellectual core)
    claims.json        # atomic statements with status
  index/
    kb.json            # GENERATED by build_kb.py
```

## Quick start (no installation, stdlib only)
```bash
python3 kb/build_kb.py                 # build the index (once / after doc changes)
python3 kb/query.py stats
python3 kb/query.py search "spectral operator zeros" -k 5
python3 kb/query.py neighbors concept-hilbert-polya
python3 kb/query.py path doc-19 concept-RH
python3 kb/query.py status refuted
python3 kb/query.py claim "Mertens"
python3 kb/query.py evaluate "Proof using only the functional equation and growth"
```

## Run as an MCP server
```bash
pip install "mcp[cli]"
python3 kb/build_kb.py
python3 kb/server.py            # stdio
```
Registration in an MCP client (example `claude_desktop_config.json` / `.mcp.json`):
```json
{
  "mcpServers": {
    "riemann-kb": {
      "command": "python3",
      "args": ["/home/user/Riemann-Hypothesis/kb/server.py"]
    }
  }
}
```

## Tools (MCP)
| Tool | Purpose |
|---|---|
| `search(query,k,status,category)` | Hybrid BM25 search + graph neighbors |
| `get_document(node_id)` | Full markdown + metadata + neighbors |
| `graph_neighbors(node_id,relation)` | Typed neighbors (relation filterable) |
| `find_path(a,b,max_depth)` | Shortest relation path between two nodes |
| `list_by_status(status)` | Documents + claims by proven/open/refuted/… |
| `get_claim(query)` | Atomic statements **with status** (anti-hallucination) |
| `evaluate_proof_idea(idea)` | Checks a proof idea against the obstructions (Doc 35/41/43/46) |
| `reasoning_scaffold(task)` | 7-step reasoning protocol (Doc 50) |
| `kb_stats()` | Metrics |

### Semantic search
`search` is hybrid: **BM25 + semantics** (neural embeddings if `sentence-transformers`
is installed; otherwise TF-IDF cosine without download) + graph expansion. Parameters `semantic`/`alpha`.

### Flagship experiment
`python3 kb/research/spacing_vs_gue.py 500` — Montgomery–Odlyzko law (zero spacings
vs. GUE), writes the result to the logbook.

## Recommended system prompt for the RH assistant
> For every claim about the RH, first call `get_claim` and respect the `status`
> (refuted ⇒ never present as true). For "is this a proof?" questions, ALWAYS use
> `evaluate_proof_idea` + `get_document('doc-35')` + `get_document('doc-43')`.
> Back up answers with `search` and mention graph neighbors (equivalences/refutations).

## Relation types in the graph
`equivalent_to, implies, reduces_to, special_case_of, generalizes, partial_result_for,
weaker_than, refuted_by, obstruction_for, evidence_for, models, blueprint_for,
attempts_transfer_of, uses, instance_of`.

## Extension (optional upgrades)
- **Embeddings**: extend `core.search` with dense vectors (sentence-transformers), score
  as `α·BM25 + (1−α)·cosine`. The interface is prepared (one scorer per chunk).
- **Tools for real mathematics**: mpmath/PARI (compute zeros/ζ) and a Lean checker
  (Doc 37) as additional MCP tools — turning the lookup server into a compute/verify server.
- **Auto-update**: rerun `build_kb.py` via CI/cron after changes to `docs/`.

## Reproducibility
`kb/index/kb.json` is generated. The sources of truth are `docs/*.md` (content) and
`kb/graph/*.json` (curated graph). After changes, rerun `build_kb.py`.
